## 一、概念重映射（设计稿词汇 → V2 架构）

设计稿是按旧架构的词汇写的，但结构上已经是域导向（五列墙、
"经济·金融 → 汇率干预"面包屑）。逐项对齐：

| 设计稿概念 | V2 概念 | 说明 |
|---|---|---|
| 频道（5 列墙）| **域**（六大域，UI 收敛五列：经济+金融合并为"经济·金融"）| 设计稿已经这么画了，颜色方点沿用 handoff 的频道标识色 |
| 簇（channel_topics，"移民潮危机 71d"）| **L4 节点**（arc/saga）| 列内分组 = 该域下活跃节点；组标签 = 节点名 + 存活天数。涌现命名，机制见蓝图 L4 |
| 故事 | **event**（stories 表不变）| 行级单位不变 |
| 断言 / 断言墙 | **宣称 / 宣称墙** | 术语已定（2026-08-08），设计稿里所有"断言"字样落地时替换，含搜索框 placeholder |
| 必读三联的选取 | **importance×新鲜度**（L2 编辑级判断，非 docs/breadth 排序）| 见 §三 |
| 簇标签点击 → 簇内故事列表 | **节点页**（新增页面）| 见 §四 |
| 频道筛选行 | 域过滤 tab | 行为不变，数据源从 channels 表换成域标签 |

## 二、原样继承的部分（handoff 说了算，不再重复取值）

- **全套 design tokens**：色板、字体三族分工（Newsreader 内容 /
  IBM Plex Sans 界面 / IBM Plex Mono 数字）、字号阶梯、间距刻度、
  面板/胶囊/徽章形状。
- **编码轴五条**（立场蓝红发散、密度单色阶、方向纯墨 ▲▼、证据层级
  实心徽章、域标识 6×6 方点）及全部禁令（红色只属于立场轴、绝不
  双纵轴、方向绝不上色）。
- **微组件**：立场微条、14 日密度带、指标胶囊、镜像条、热力矩阵。
- **页面骨架**：顶栏 + tab 栏 + 域过滤行。
- **四个次要页**：阅读（3a）、市场快照（4a）、画报（4b）、周复盘
  （4c）按 handoff 原样实现——它们不涉及层级架构，无需重映射。
  阅读页的"关联故事"指向 event，语义不变。
- **交互契约**：引用码定位（不用 scrollIntoView）、表格视图、hover/
  focus 同路径 tooltip、骨架加载态、失败隔离的错误态、空态要说明原因。
- **深色主题**方向与 dataviz 校验器要求。

## 三、头版（2a）的 V2 调整

布局完全按设计稿（必读三联 + 五列域墙 + 未解问题带，**墙绝不退化
成单列**）。变的是选取与排序逻辑：

1. **必读三联**：候选 = 活跃 event 与热节点混排，排序键
   `importance DESC, 新鲜度衰减, velocity`。importance 来自 L2 编辑级
   判断（P1 落地），不再是 docs+3×breadth 的印证计数。
2. **单源未印证角标**：importance ≥4 且 breadth == 1 的第一报直接上
   必读位，标 `单源未印证`（Mono 10px，`ink-4`，不用红——红只属于
   立场轴和印红标记）。这是特性：编辑部抢头条也这么干。
3. **域墙列内分组**：组 = 该域下按活跃度取的 L4 节点，组内 event 行
   按三档权重（必读/重点/其余——档位判定改用 importance 分档，视觉
   语法照 handoff 三档表）。standalone event（无父节点）平铺在列尾，
   不硬造"其他"组。
4. **多域节点去重**：节点标注多个域时，墙上只出现在**主域**列
   （L4 标注时第一个域即主域）；域 tab 过滤视图里则全部出现。
   同一屏一条故事只出现一次——NYT 头版也不会把一条新闻印两遍。
5. **未解问题带**：不变，恒在最后。

## 四、新增页面：节点页（arc/saga detail）

设计稿没有这一页（旧架构里簇只是标签）。V2 里节点是一等公民，
点击簇标签/必读卡面包屑进入。**不另起设计语言，完全复用 2b 故事
详情页的骨架**，差异如下：

- **面包屑**：DAG 多父全列——`经济·金融 / 汇率干预 · 美日关系`，
  多父用 ` · ` 并列，每段可点。递归层级逐段展开。
- **头部**：节点名（34px 同 2b 主标题）+ 一句话入簇标准（Newsreader
  400 15px `ink-2`，这是 L4 归簇时 LLM 给的 hint）+ 上滚标量胶囊
  （去重后的 docs/breadth/velocity、importance=后代 max、存活天数、
  子节点数）。
- **主体左栏**：子节点/子 event 列表（沿用域墙的两行行语法：标题行
  + 指标行，按 importance 排），递归节点先列子节点组再列直属 event。
- **主体右栏**：节点级时间线（各子 event 的关键宣称按时间合流，
  沿用 2b 时间线语法）+ 未解问题上滚。
- **不做**：节点级综述/宣称墙/分歧矩阵（那些是 event 级资产；
  节点页是导航枢纽不是内容终点，别把它做重）。

## 五、故事详情页（2b）的 V2 调整

- 面包屑从 `域 / 簇` 改为 DAG 全路径（同 §四），多父并列。
- 其余（三栏头部、综述引用码、宣称墙、分歧矩阵主舞台、时间线、
  实体、文档列表）按设计稿原样。"断言"字样全部落"宣称"。

## 六、API 合同

前端不硬编码任何域/节点（域列表也来自接口——六域虽然稳定，
但归 LLM 词表管，不归前端管）。

**沿用**（P3a 就能跑）：`/health`、`/api/stats`、`/api/stories/{id}`、
`/api/admin/tokens`、`/api/admin/sources`、`/api/runs`。

**新增**（标注依赖的后端阶段）：

| 接口 | 返回 | 依赖 |
|---|---|---|
| `GET /api/front?window=72h` | 必读候选 + 各域墙（节点组 + event 行，含 importance/scalars/立场微条数据）+ 未解问题带 | P1（importance）；P2 前节点组降级为"域内直接平铺 event" |
| `GET /api/nodes/{id}` | 节点详情：父链（多父）、子节点、直属 event、上滚标量、合流时间线 | P2 |
| `GET /api/domains` | 域列表（名字、UI 色 token 名、活跃计数）| P1 可用静态六域，P2 接词表 |
| 阅读/市场补口 | 读时估算、关联 event、observations 序列 | 与 P3c 同期补 |

**退役**：`/api/channels*` 随 P4 下线；P3 期间新旧前端并存时保留只读。

## 七、技术栈与组件清单

**React + Vite**（handoff 推荐，用户已确认愿意换框架）。后端沿用
Personal Coach 的路子：`service.py` 把 `StaticFiles(web_dir)` 换成
serve `web/dist`，API 路由不动，单端口同源。

必须组件化的重复单元（否则重蹈"功能堆出来、样式后补"）：
`StoryRow`（两行行，三档变体）/ `NodeGroup`（簇组头）/ `MetricChip` /
`StanceStrip`（立场微条，行内/卡片两尺寸）/ `DensityBand`（14 日带）/
`TierBadge`（证据层级）/ `DomainDot` / `Breadcrumbs`（DAG 多父）/
`CiteCode`（引用码）/ `PanelSkeleton`。图表（分歧矩阵、热力矩阵、
共轴时间带）做成薄封装，数据进 props，编码轴颜色从 tokens 引用。

## 八、分期（与后端 P1/P2 的依赖关系）

- **P3a**（依赖 P1）：设计系统底座（tokens/字体/微组件）+ 头版 +
  故事详情页。节点组暂缺时头版降级为域内平铺——布局不变，只少
  一层组标签。旧前端保留在 `/legacy` 直到 P3c 完成。
- **P3b**（依赖 P2）：节点页 + 头版接入真实节点组 + DAG 面包屑。
- **P3c**：阅读/市场/画报/周复盘四页迁移 + 深色主题完整稿（过
  dataviz 校验器）+ 下线旧前端。
- 每页完成后与 `design-handoff/screens/` 对应截图逐块比对（层级、
  密度、三档权重拉开程度）；取值以 token 表为准，不从截图吸色。

## 九、验收清单（每页发布前过一遍）

1. 头版一屏 ≥30 条故事可扫视，墙是横向的（单列 = 失败，handoff 原话）。
2. 三档权重在字号/字重/颜色/可视化四处同时成立。
3. 红色只出现在：立场轴 +2、印红"必读"标记、当前 tab 下划线、
   阅读页"存疑"竖线与"读原文"。其余任何红都是 bug。
4. 数字全部等宽；方向符号全部纯墨。
5. 图表全部有表格视图；分位分档的阈值全部明示。
6. 浅/深两主题下文字对比度 ≥4.5:1（三级 ≥3.6:1）。
7. 术语：界面上没有"断言"，只有"宣称"；没有"频道"，只有"域"。
