# Handoff: NewsAssistant 全站视觉重做

## Overview

NewsAssistant 是一个单用户的个人信息平台：自动化流水线抓取新闻源 → LLM 做实体抽取 / 事件归并 / 立场分析 → 呈现为「故事」而非原始文章列表。范围锁定政治、地缘政治、经济、金融、Business、科技六类。部署在自有服务器，Tailscale 私网访问，桌面浏览器为主，非公开产品。

本次交付是**全站统一重做**：先定一套设计语言（色板 / 字重字号阶梯 / 间距节奏 / 卡片与列表的视觉语法），再让所有页面遵守它。

重做要解决的两个具体问题（用户原话）：

1. 视觉不精致 —— 配色 / 字体 / 间距没有统一系统，像内部工具不像成熟产品。
2. **「信息还是从上往下排列，我还是一条一条从上往下看，那我搞这个有什么意义呢，完全没有充分利用空间。」** ——
   这是最重要的一条。**首页必须是一面可以横向扫视的墙，不是一条纵向队列。**
   实现时如果把频道墙退化成单列纵向流，这次重做就失败了。

信息密度要**高**（这是给自己用的信息工具，不是营销落地页），但密度问题要用**视觉层级**解决，不是靠留白牺牲信息量。

## About the Design Files

`newsassistant-designs.dc.html` 是**设计参考**，不是可以直接上线的生产代码。它是一份 HTML 原型，用来表达最终的视觉与信息层级意图。

任务是**在目标代码库的环境里重建这些设计**，使用该环境已有的模式与库；本项目当前没有前端框架（纯 HTML/CSS/JS，Python 后端直接 serve 静态页），用户已明确愿意更换。

**推荐技术栈：React + Vite**，理由：
- 用户另一个项目（Personal Coach）用的就是这套，模式熟悉；
- 后端沿用同样的「单端口同源 serve 打包产物」路子 —— `newsassistant/service.py` 里现在挂的是 `StaticFiles(directory=web_dir, html=True)`，改成 serve `web/dist` 即可，其余 API 路由不动；
- 这些页面里大量重复的「故事行 / 簇分组 / 指标胶囊 / 密度带 / 立场条」必须组件化，否则会重蹈「功能堆出来、样式后补」的覆辙。

⚠️ 打开设计文件需要同目录下的 `support.js`（本包已附）。文件本身是一张设计画布：**从上往下依次是 Turn 4 / Turn 3 / Turn 2 / Turn 1**，最新的方案在最上面。**Turn 1（1a / 1b / 1c）是已被否决的方向探索，不要实现**，保留只为记录取舍过程。

要实现的是：**5a、5b、5c、2b、3a、4a、4b、4c** 八个页面。

⚠️ **`2a` 已被 `5a` + `5b` 取代，不要实现 `2a`。** 2a 把「全部故事」倒在首页上（每频道一长串、highlight 未必最新），用户否决了这个逻辑。2a 的稿子保留在文件里，只作为微组件与三档权重的取值参考（见本文档「附录 A」）。

### 页面层级（Turn 5 定稿，实现时必须遵守）

| 层 | 页面 | 回答的问题 | 内容纪律 |
|---|---|---|---|
| 1 | **头版** `5a` | 今天最重要的是什么 | 只放最新且最重要的。1 条头条 + 5 段模型综述 + 刚刚更新流。**不放完整列表** |
| 2 | **板块页** `5b` | 这个板块的全貌 | 板块综述 + 按簇分组的完整清单 + 存量未解问题。六个板块共用同一套版式 |
| 3 | **簇页** `5c` | 这条线整体在往哪走 | 只放跨故事的东西：共轴时间带、簇内共识/分歧、主线漂移、共享实体、相邻簇 |
| 4 | **故事页** `2b` | 一件事看透 | 分歧矩阵为主舞台 |

三条首页纪律（用户明确要求）：① 首页每条都带绝对时间戳，排序按**最新写入时间**（不是 velocity）；② 单个板块在首页最多露 1 主 + 2 次，超出走「进入板块」；③ 头条的价值靠**模型写的综述句子**承担，不靠指标堆。

## Fidelity

**High-fidelity（hifi）。** 颜色、字号、字重、行高、间距、圆角、投影都是最终值，按本文档的 token 表逐一落实。文案是示意内容（虚构数据），**不要照抄进产品**，但文案的**语气和信息结构**要保留 —— 例如「19 家独立信源里 11 家用了『未确认』这个措辞」这种句式，说明的是摘要应该给出**可核查的分歧结构**，而不是泛泛复述。

### 1 · 头版首页（`5a`，宽 1440）

**目的**：进来 10 秒知道今天最重要的是什么。**这是一份报纸的头版，不是一个索引页。**

实现时最容易犯的错：把它做成「按 velocity 排序的故事列表」。首页的每一条都必须通过两道筛子——**够新**（近 4h 有写入）且**够重要**（今日新增断言数 / 分歧结构变化 / 独立源改口径的幅度）。选不出来就少放，不要凑数。

**tab 栏**：头版 / 政治 / 地缘 / 经济·金融 / 科技 / Business（当前项 `#1A1A17` + 600 + `border-bottom:2px solid #9E2B25`）。右侧一行运行统计 `今日入库 412 篇 / 41 源` + `新故事 3 · 更新 17 · 合并 2`（Mono 10.5px）。顶栏运行胶囊改为 `08-11 周二 · 最近合成 08-11 14:26 · 6m 前`——**绝对时间 + 相对时间同时给**，全站所有时间戳都照此规则。

**布局**（外壳 `#F5F4F1`，内容区 `padding:16px 18px`，纵向 `gap:14px`）：

1. **头条区** `grid-template-columns:1.62fr 1fr`，`gap:14px`。
   - **左：唯一头条大卡**（`padding:20px 24px`）。`今日头条` 印红胶囊（底 `#F7ECEA` 字 `#9E2B25`）+ 频道→簇路径 + 右对齐 `14:20 更新 · 6m 前`。标题 Newsreader 600 · **32px** / 1.2 / `-.015em`。正文 Newsreader 400 · **17px** / 1.68，**写的是「今天新增了什么」而不是故事全貌**（例：「今天下午的新信息只有一条：日银纪要公布，未提汇率协调——这把分歧从『规模多少』推到了『谁授权的』」），每句带引用码。下面一条 `为何在头版` 说明条（底 `#FAF9F6` · 边 `1px #EDEBE6` · radius 6 · `padding:12px 14px`）：左侧 64px 宽 uppercase 标签 + Newsreader 14.5px 的**筛选理由**（例：「19 个独立源里 11 个改了措辞，一天内新增 3 条可核查断言，且分歧结构从单峰变成两极——变化幅度是今天最大的」）。**这条是首页可信度的关键，必须由后端给出可解释的排序依据，不能前端编。** 最后是指标胶囊组。
   - **右上：`刚刚更新` 流**（面板，按**写入时间倒序**，近 4h，5 条）。每行：时间戳（Mono 10.5px，宽 34）+ 标题（Newsreader 500·14.5px 前两条 / 400·14px 其余）+ 一行 `汇率干预 · +1 断言 · 分歧 +18`（Mono 10px）——**写的是这次更新改变了什么**，不是故事简介。这块解决用户提的「highlight 未必是最新的」。
   - **右下：`今天该知道的第二件事`** 卡（标题 Newsreader 600·19px，一段 14.5px 摘要 + 指标胶囊）。
2. **板块综述行** `grid-template-columns: repeat(5, 1fr)`，`gap:14px`。每列一个面板，**这是首页与 2a 频道墙的根本差别——每个板块只露 1 主 + 2 次，不是一长串**：
   - 面板头：6×6px 频道色方点 + 频道名（Newsreader 600·14px）+ 右对齐 `今日 4 条更新`（Mono 10px）
   - **板块综述**（`padding:13px 14px`，Newsreader 400 · 14px / 1.6，`ink-2`）：**模型自己写的一段话，说这个板块这半天发生了什么、共同主题是什么**（例：「今天的动向都指向同一件事：欧洲各国在把临时边境措施变成常设安排，法案层面首次出现内阁分裂」）。今天没有新事件的板块要**如实说**（例：「今天没有新事件，只有一条推进：……」），不要拿旧闻填。这段是本次重做的产品核心，不是装饰。
   - `最新事件` uppercase 小标 + 右对齐时间戳 → 一条主事件（Newsreader 500·15.5px）+ 指标行（跨度 / 源数 / velocity 墨色 600 / 26×4 立场微条右对齐）
   - 上边 `1px #F5F4F1` 分隔后 2 条次条：时间戳（Mono 10px，宽 **46px** + `white-space:nowrap`，要容纳 `昨 21:30`）+ 标题（Newsreader 400·13.5px `ink-2`），**不带指标**
   - 面板底 `margin-top:auto` 固定一行 `进入政治 · 另有 12 条在追 →`（Mono 11px `label`）→ 跳 `5b`
3. **`今天新出现的问题`** 整幅面板，`repeat(3, 1fr)`，`gap:20px`。**只列今日新增的问题**，存量推到板块页（左侧标签区写明 `仅列今日新增 · 存量 12 条在板块页`）。每条左侧 `2px solid #E5E2DC` + 问题（Newsreader 14px）+ `14:20 提出 · 3 源 · 0 回答`。

**一屏容量**：14 条（1 头条 + 1 次条 + 5 条刚刚更新 + 5 主 + 10 次 + 3 问题，视口内约 14 条可读条目）。比 2a 的 31 条少一半，是有意的——密度让位给「每条都值得看」。

### 2 · 板块页（`5b` 政治，宽 1440 · 六个板块共用）

**目的**：首页放走的密度全部落在这里。政治 / 地缘 / 经济·金融 / 科技 / Business / 其他 六个板块**共用同一个组件**，只换数据与频道色。

**顶栏**：搜索框占位改成 `在政治内搜索`。**tab 栏右侧是排序器**：按更新（默认）/ 按 velocity / 按分歧 / 按跨度（Mono 10.5px，当前项 `ink`）。

**板块头部**（`#fff` 整幅，`padding:20px 24px 18px`，三栏 flex，`1px #F0EEE9` 竖线分隔）：
- 左（flex:1，max-width 860）：7×7 频道色方点 + `政治`（Newsreader 600·26px）+ `16 个在追故事 · 4 簇 · 今日 4 条更新` → **板块综述**（Newsreader 400 · 17px / 1.68，带引用码）：说的是**这个板块本周的重心怎么移动的**，例「重心从『选举日程』移到了『边境法制化』：三个国家在同一周把临时措施写进常设法案，而反对意见第一次出现在执政联盟内部而非议会外」。
- 中（宽 210）：`本板块 14 日报道量` 密度带（14 格，`height:26px`，`gap:2px`）+ `今日 118 篇 / 21 源 · ▲34%`
- 右（宽 250）：`簇` 清单，每行簇名（有今日更新的 `ink` + 500，其余 `ink-3`）+ 右对齐 `6 故事 · 71d`

**主体** `grid-template-columns:1fr 320px`，`gap:14px`，`padding:16px 18px`。

**左栏 = 按簇分组的完整清单**（不是平铺列表）。每个簇一个面板：
- 簇头（`padding:13px 20px`，下边 `1px #EDEBE6`）：簇名（Sans 600·11px uppercase）+ `6 故事 · 跨度 71d · 今日 2 条更新` + 右对齐 `簇综述 ⌄`。**簇名可点 → `5c` 簇页。**
- 簇内按最新更新排序，行分三档，`1px #F5F4F1` 分隔：
  | 档 | 版式 |
  |---|---|
  | 今日主更新 | 时间戳 52px + 标题 Newsreader 600·19px + 两行摘要 14.5px + 完整指标胶囊组（含分歧微条 40×5 与 `L1 · L3`） |
  | 今日次更新 | 标题 500·16.5px + 一行摘要 13.5px + Mono 指标行（含 34×5 立场微条） |
  | 更早 | 标题 400·15px `ink-2` + Mono 指标行，`ink-4`，**不带立场微条** |
- **今日无更新的簇默认折叠**成一条（`padding:13px 20px`）：`司法与选制 · 联盟内政` + `5 故事 · 今日无更新 · 已折叠` + 右对齐 `展开 ⌄`。

**右栏三块面板**：
1. **未解问题** —— 本板块**存量全部**（首页只给今日新增的那部分在这里落地），今日新增的排最前并标 `今日 12:35`，旧的降到 `ink-2`。
2. **高频实体** —— 胶囊组，近 7 日按 IDF，前两名带 6×6 实心方块 + `ink`，第三名圆点 + `ink-2`，其余 `ink-3`，每枚带出现次数。

## Interactions & Behavior

- **导航**（四层，路由必须显式建出来）：`/`（头版 5a）→ `/s/:section`（板块页 5b）→ `/c/:cluster`（簇页 5c）→ `/story/:id`（故事页 2b）。故事行 / 头条卡整块可点 → 故事页；板块名与「进入政治 →」→ 5b；簇名与簇折叠条 → 5c；`相邻簇` 行 → 另一个 5c；实体胶囊 → 实体页。面包屑在 5b/5c/2b 上恒显示完整路径。
- **首页排序**：默认按最新写入时间；筛选逻辑（够新 + 够重要）与「为何在头版」的理由由后端给出，前端只渲染。板块页可切排序，**首页不可切**——头版是编辑判断，不是可排序的表格。
- **引用码**：详情页综述里的 `c1` 可点 → 滚动定位并高亮断言墙对应行（**不要用 `scrollIntoView`**，用容器 `scrollTop` 计算）。
- **hover**：列表行 hover 底色 `#FAFAF8`；胶囊与徽章不做 hover 变化；可点文字 hover 加下划线。
- **图表**：每个图必须提供**表格视图**切换；tooltip 对 hover 与键盘 focus 走**同一路径**。
- **时间窗切换**（24H/72H/7D/30D）与排序切换：客户端重新请求，不做整页刷新。
- **主题切换 `◐`**：浅色 / 深色，写入 localStorage 并在载入时恢复。
- **加载态**：面板骨架用 `#F0EEE9` 块，保持最终布局的行数与高度，避免跳版。
- **错误态**：频道查询返回 422（`BadQuery`，配置错误不是 500）时，在该频道面板内显示查询出错与原因，其他频道照常渲染 —— 沿用后端的失败隔离原则。
- **空态**：结构检测未触发的视图要**显式说明为什么没有**（「这个频道没有链路图，因为 depends 边不足以拓扑排序」），不能只是不渲染 —— 否则用户会以为页面坏了。

## State Management

- `channels`、`activeChannel`、`timeWindow`（24H/72H/7D/30D）、`sortKey`（velocity/breadth/disagreement/updated）
- `storiesByChannel`（含 `scalars` 与 `series`）、`storyDetail`（summary / timeline / open_questions / claims / events）
- `readingQueue`（含 `readMinutes`、`tier`、`linkedStories`）、`readTimeFilter`
- `marketSnapshot`（normalized series + narrative density + divergence board）
- `theme`（light/dark，持久化）、`health`（cycle 状态，轮询）

数据全部来自现有只读 API，前端不硬编码任何频道（D3：频道是一条保存的查询，请求时执行）：

| 页面 | 接口 |
|---|---|
| 顶栏状态 | `GET /health` · `GET /api/stats` |
| 首页信息流 | `GET /api/channels` · `GET /api/channels/{key}/stories` |
| 结构检测（决定主舞台） | `GET /api/channels/{key}/structure`（未触发的检测器也会返回，用于空态说明） |
| 故事详情 | `GET /api/stories/{id}` |
| 复盘 · 成本 | `GET /api/admin/tokens` |
| 复盘 · 信源 | `GET /api/admin/sources` |
| 复盘 · 运行 | `GET /api/runs` |

阅读板块与市场快照所需的字段（读时、关联故事、observations 序列）当前 API 未覆盖，需要后端补接口。

## 深色主题

两套都要经得起看，**深色不是把浅色反过来**。设计稿只给了色板方向（在 Turn 1 各方案底部的深色条里），完整深色稿尚未出：
- 底色降到 `#0E1116`–`#191714` 区间（跟随浅色的暖轴），面板靠**明度分层**抬升一档，而不是靠描边；
- 立场蓝红需**提亮并降饱和**（参考 `#7FA8D4` / `#D96B62`）才能在暗底保持 CVD 分离度；
- 文字三档的对比度下限与浅色一致（≥4.5:1 / ≥3.6:1），不要在深色下偷偷降。

任何配色改动都必须过 dataviz 校验器（CVD 分离度 / 对比度 / 单调性）。
