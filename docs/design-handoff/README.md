# Handoff: NewsAssistant 全站视觉重做

## Overview

NewsAssistant 是一个单用户的个人信息平台：自动化流水线抓取新闻源 → LLM 做实体抽取 / 事件归并 / 立场分析 → 呈现为「故事」而非原始文章列表。范围锁定政治、地缘政治、经济、金融、Business、科技六类。部署在自有服务器，Tailscale 私网访问，桌面浏览器为主，非公开产品。

本次交付是**全站统一重做**：先定一套设计语言（色板 / 字重字号阶梯 / 间距节奏 / 卡片与列表的视觉语法），再让所有页面遵守它。

重做要解决的两个具体问题（用户原话）：

1. 视觉不精致 —— 配色 / 字体 / 间距没有统一系统，像内部工具不像成熟产品。
2. **「信息还是从上往下排列，我还是一条一条从上往下看，那我搞这个有什么意义呢，完全没有充分利用空间。」** ——
   这是最重要的一条。**首页必须是一面可以横向扫视的墙，不是一条纵向队列。**
   实现时如果把频道墙退化成单列纵向流，这次重做就失败了。

信息密度要**高**（这是给自己用的信息工具，不是营销落地页），但密度问题要用**视觉层级**解决，不是靠留白牺牲信息量。

## About the Design Files

`newsassistant-designs.dc.html` 是**设计参考**，不是可以直接上线的生产代码。它是一份 HTML 原型，用来表达最终的视觉与信息层级意图。

任务是**在目标代码库的环境里重建这些设计**，使用该环境已有的模式与库；本项目当前没有前端框架（纯 HTML/CSS/JS，Python 后端直接 serve 静态页），用户已明确愿意更换。

**推荐技术栈：React + Vite**，理由：
- 用户另一个项目（Personal Coach）用的就是这套，模式熟悉；
- 后端沿用同样的「单端口同源 serve 打包产物」路子 —— `newsassistant/service.py` 里现在挂的是 `StaticFiles(directory=web_dir, html=True)`，改成 serve `web/dist` 即可，其余 API 路由不动；
- 这些页面里大量重复的「故事行 / 簇分组 / 指标胶囊 / 密度带 / 立场条」必须组件化，否则会重蹈「功能堆出来、样式后补」的覆辙。

⚠️ 打开设计文件需要同目录下的 `support.js`（本包已附）。文件本身是一张设计画布：**从上往下依次是 Turn 4 / Turn 3 / Turn 2 / Turn 1**，最新的方案在最上面。**Turn 1（1a / 1b / 1c）是已被否决的方向探索，不要实现**，保留只为记录取舍过程。

要实现的是：**2a、2b、3a、4a、4b、4c** 六个页面。

## Fidelity

**High-fidelity（hifi）。** 颜色、字号、字重、行高、间距、圆角、投影都是最终值，按本文档的 token 表逐一落实。文案是示意内容（虚构数据），**不要照抄进产品**，但文案的**语气和信息结构**要保留 —— 例如「19 家独立信源里 11 家用了『未确认』这个措辞」这种句式，说明的是摘要应该给出**可核查的分歧结构**，而不是泛泛复述。

### 1 · 首页信息流（设计文件里的 `2a`，宽 1440）

**目的**：一屏看清「今天有什么值得看」，横向扫视，不做纵向队列。设计稿一屏容纳 **31 条故事 + 5 个频道 + 4 条跨故事未解问题**。

**布局**（外壳 `#F5F4F1`，内容区 `padding:16px 18px`，纵向 `gap:14px`）：

1. **第二行 tab 栏下方**还有一条频道筛选行：全部 / 政治 / 地缘 / 经济·金融 / 科技 / Business，右侧排序（按 velocity / breadth / 分歧 / 更新，Mono 10.5px）。
2. **必读三联**：`grid-template-columns:1.25fr 1fr 1fr`，`gap:14px`。左侧大卡多一段摘要和一条 14 日密度带；右两卡结构相同、字号降一档。
3. **频道墙**：`grid-template-columns: repeat(5, 1fr)`，`gap:14px`。**这是全站最关键的一块 —— 五个频道并列成列，绝不可退化成纵向单列。** 每列是一个面板：
   - 面板头：6×6px 频道色方点 + 频道名（Newsreader 600 · 14px）+ 右对齐的 `6 · 2 簇`（Mono 10px · `ink-4`）
   - 列内按**簇**（语义涌现出的主题簇，如「移民潮危机」「汇率干预」，非预设分类）分组：簇标签（uppercase 10px）+ 簇存活天数
   - 每行两行制：标题行 + 指标行；行间 `1px #F5F4F1`
4. **未解问题带**：整幅宽度一个面板，`grid-template-columns: repeat(4, 1fr)`，`gap:20px`，每条左侧 `2px solid #E5E2DC` 竖线 + 问题（Newsreader 14px）+ 出处（Mono 10.5px）。位置恒在最后。

**故事行三档权重**（用户明确要求同时用尺寸 / 颜色 / 版式 / 留白节奏 / 指标可视化五种手段）：

| 档 | 版式 | 标题 | 指标行 |
|---|---|---|---|
| 必读 | 独立大卡，带摘要 + 密度带 | Newsreader 600 · 19–25px · `ink` | 胶囊组，含分歧微条 |
| 重点 | 频道列内两行行 | Newsreader 500 · 15px · `ink` | Mono 10.5px `ink-4`，velocity 用 `ink` + 600，**带**立场微条 |
| 其余 | 频道列内两行行 | Newsreader 400 · 14px · `ink-3` | Mono 10.5px `ink-4`，**不带**立场微条 |

三档的差别必须同时体现在**字号、字重、颜色、是否带可视化**四处 —— 少一处层级就塌。

**常驻派生指标**（用户选定，卡片上必须常驻）：velocity（`▲212%` / `▼8%` / `—`）、立场分歧度（5 段微条 + 数值）、时间跨度与最新更新（`跨度 11d · 更新 6m 前`）、来源分布（`19 独立源` + 证据层级 `L1·L3·L5`）。docs 数与 breadth 也在列。

**微组件**：
- *立场微条*：5 段 flex，`gap:1px`，行内版 `width:26px;height:4px`，卡片版 `width:40–44px;height:5px`；段宽按各档信源数取 flex 比例。
- *14 日密度带*：14 格 flex，`gap:2px`，`height:12–14px`，`border-radius:1px`，色取密度阶。
- *指标胶囊*：`padding:6px 9px` · radius 5 · 底 `#F2F1ED` · Mono 11px；velocity 项字重 600。

### 2 · 故事详情页（`2b`，宽 1440）

**目的**：看透一件事 —— 来龙去脉 + 各方分歧在哪。

**面包屑行**：`NewsAssistant / 经济·金融 / 汇率干预`，右侧 `story #4127 · active · 已合成 6m 前` 胶囊。

**头部区**（`#fff` 整幅，`padding:22px 26px 18px`，三栏 flex，用 `1px #F0EEE9` 竖线分隔）：
- 左（flex:1，max-width 820）：必读标记 + 簇归属 → 主标题 34px → 标量胶囊组（`84 docs` / `19 独立源 / 84 篇` / `velocity ▲212%` / `stage 4` / `一致度 38` / `跨度 11d · 更新 6m 前`）
- 中（宽 300）：**立场天平** —— 5 段横条 `height:34px` `border-radius:4px`，下方各档计数（`−2 · 4` … `+2 · 4`），再下一句人话解读（Newsreader 13px）
- 右（宽 230）：**证据层级分布** —— L1/L3/L5/L6 横条（密度阶实心，宽度按篇数），底部一行 `转述折叠：128 篇 → 84 篇 → 19 独立源`

**主体**：`grid-template-columns:1.55fr 1fr`，`gap:14px`。

左栏三块：
1. **综述** —— Newsreader 400 · 17px / 1.72。**每句话后面跟一枚可点的引用码**（`c1` `c4`，Mono 10px，底 `#F2F1ED`，`padding:3px 5px`，radius 3，`vertical-align:2px`）。无引用的句子在写入端已丢弃，前端不需要兜底，但引用码必须可点开定位到断言。
2. **断言墙** —— 按分歧度排序。每行：claim id（宽 22）+ 断言文本（重要 500·16px `ink` / 次要 400·15px `ink-2`）+ 元信息（`9 源支持` `7 源反对` `3 源未表态` `分歧 91`（高分歧用 `#9E2B25`）`L5 · L6`）+ 右侧 120×16 的五段立场条。
3. **分歧矩阵** —— **这是本页主舞台，占最大面积**（项目核心资产：参照产品做不出来，因为它们没有 claim 层）。行 = 断言（左侧 Mono id 列，行高 16px，`gap:3px`），列 = 19 个转述折叠后的独立源（按证据层级排序），单元格 `height:16px` `border-radius:2px`，色取立场五档，`#F5F4F1` = 该源未提及。底部图例：`反对 ▮▮▮▮▮ 支持` + 列的含义 + 「表格视图 ⌄」（无障碍要求：每图必须有表格视图，tooltip 对 hover 与键盘 focus 走同一路径）。

右栏四块：
1. **时间线** —— 竖线 `1px #E5E2DC`（`margin-left:4px;padding-left:16px`），节点 7×7 圆点（近期 `#1A1A17`，较早 `#8B8779`，更早 `#C9C6BE`），每条：时间戳（Mono 10.5px）+ 事件（Newsreader 14.5px）+ 引用码。
2. **未解问题** —— 左 `2px solid #E5E2DC` 竖线，问题 + `3 源提出 · 0 源回答`。
3. **参与实体** —— 胶囊组，按 IDF 权重排序，权重高的带实心方块 + `ink`，低的降到 `ink-3`；每枚带出现次数。
4. **文档列表** —— 每行：层级徽章 + 标题 + `mof.go.jp · 08-10 · 原发` / `原发 · 被 23 家转发`（转述溯源要显式呈现）。

### 3 · 阅读板块（`3a`，宽 1440）

**目的**：论文 / 技术博客 / 实验室发布这类非新闻内容的预消化视图。

**关键设计决策**：这里**没有多源分歧**，立场轴是空的，所以派生量整套换掉：
- **读时** —— 时间预算是这里唯一的稀缺资源。顶栏常驻 `未读 47 · 本周新增 23 · 预计读完 6h12m`；筛选器就是读时档位（全部 / <5m / 5–15m / 15m+）。
- **证据强度** —— 沿用 L1–L7。
- **关联故事** —— 每条指回它解释的新闻侧活跃故事。**这是阅读板块与信息流真正接上的地方，也是它值得存在的理由**，务必实现。

**三档结构**（保留原来的杂志式三档，但重新定义）：

1. **精读**（2 条，`grid-template-columns:1fr 1fr`）—— 完整预消化卡。头部：层级徽章 + 出处说明（`arXiv · 预印本 · 未经同行评审`）+ 右对齐读时胶囊。标题 Newsreader 600·23px，副行作者/日期/版本。**四栏预消化**（`grid-template-columns:1fr 1fr`，`gap:14px`），每栏左侧 2px 竖线 + uppercase 小标题 + Newsreader 14.5px 正文：
   - `主张` —— 竖线 `#1A1A17`
   - `新在哪` —— 竖线 `#8B8779`
   - `方法与证据` —— 竖线 `#8B8779`
   - `存疑` —— 竖线 `#B0403A`（**全页唯一的红**）
   底部分隔线下：`关联故事` 胶囊组（带各自 docs 数）+ 右对齐 `读原文 ↗`（`#9E2B25`）。
2. **队列**（4 列：论文 / 技术博客 / 实验室发布 / 长文·报告）—— 每列面板头带频道色方点 + `12 未读 · 3h04m`。每条三行：标题 + **一句话消化**（Newsreader 13px `ink-3`，这句是这个板块的产品核心，不是摘要而是结论）+ 指标行（读时 `ink` / 层级 / `关联 2`（`#9E2B25`））。有关联故事的排前。
3. **已消化**（整幅面板）—— `grid-template-columns: repeat(3, 1fr)`，`gap:10px 24px`。每条：日期（Mono 10.5px，宽 34）+ 标题（`ink-2`）+ `—— 结论一句`（`ink-3`）。右上角 `全部归档 ⌄`。

### 4 · 市场快照（`4a`，宽 1440）

**目的**：回答「叙事和数字对不对得上」。

**上半**：`grid-template-columns:1.9fr 1fr`。

左：**共轴时间带**。
- **硬约束：绝不双纵轴。** 所有序列归一化到 30 日前 = 100，共用一根轴，终点直标。
- 实现要点（设计稿踩过的坑，务必照做）：绘图区与下方密度带、日期刻度必须**严格共轴**。做法是外层容器 `padding-right:62px` 留出轴标签沟槽，SVG 用 `viewBox="0 0 700 210"` + `width:100%` 铺满绘图区，轴标签（115/100/85）用绝对定位的 HTML 放进沟槽（不要放进 SVG，否则 `preserveAspectRatio` 会让它们错位），密度带与日期行宽度设为 `calc(100% - 62px)`。三者左右边界必须逐像素对齐 —— 一个标着「单轴」的面板如果实际错位 6%，它就是在撒谎。
- 四条序列用**墨色深浅 + 虚线样式**区分（抗色觉缺陷），不用彩色系列色：`#1A1A17` 实线 / `#63605A` 虚线 5-3 / `#8A8781` 实线 / `#2F5D8C` 点线 2-3。图例在下方，终点值直标。
- 下方 **同轴叙事强度**：30 格密度带 + 日期刻度 + **分档阈值图例**（`0–4 · 5–11 · 12–23 · 24–41 · 42+ 篇/日` —— 分位分档的阈值必须明示，否则非线性间距会误导）。

右：**背离榜**。每行：标的名 + `背离 +38`（Mono 600）+ 一对镜像条（左条右对齐 = 叙事强度分位，中间 1px 分隔，右条左对齐 = 30 日价格变动分位），条色取密度阶。底部一句解读。

**下半**：**标的表**，`grid-template-columns:1.6fr .8fr .6fr .6fr .6fr 1.1fr 2fr`。列：标的（Sans 13px）/ 最新 / 1d / 5d / 30d（全 Mono 12px 右对齐，方向用 ▲▼ 墨色，30d 字重 600）/ 叙事强度（密度条 + 数值）/ 关联故事（Newsreader 13px）。无关联故事的行整体降到 `ink-3` 并写 `无活跃关联故事`。只列有 `observations` 记录的标的。

### 5 · 每日画报（`4b`，宽 1080）

**目的**：一天的形状。**六个页面里唯一允许留白的**，其余五个都要顶到高密度。

- **报头**（`padding:30px 34px 24px`）：`画报 · 2026-08-09 · 周日` + 右侧 `318 篇归档 · 6 个新故事 · 2 个转入沉寂`；下方一句引语式的判断（Newsreader 600 · 40px，如「日元干预吃掉了全天 26% 的归档量」）+ 右侧三个大数（峰值时段 / 独立源 / 转述折叠率，Mono 26px）。
- **频道 × 小时热力矩阵**（主体）：5 行 × 24 列，格 `height:20px` `border-radius:2px` `gap:2px`，行标签宽 74 右对齐；轴刻度 `00 / 06 / 12 / 18 / 23`；阈值写在标题旁。当日主导频道的行标签加粗到 600。

### 6 · 周复盘（`4c`，宽 1440）

**目的**：看的不是新闻，是**这套系统自己这周干得怎么样**。

**上排** `grid-template-columns:1.15fr 1fr 1fr`：
1. **故事生命周期** —— 四个大数（新建 31 / 吸收合并 9 / 分裂 3 / 转沉寂 17，Mono 30px）+ 「值得看的三次纠错」：事件徽章（`分裂` `#4A473C` / `合并` `#63605A` / `漂移` `#B0403A`）+ 描述 + `触发：合格实体不再相交` 这类判据。数据来自 `story_events`（event-sourcing，「为什么这篇被归到这个故事」必须可追）。
2. **未解问题解答率** —— `33%` 大数 + 三段条（已答 / 部分 / 仍开）+「悬置最久」列表（带悬置天数）。

1. **信源表现表** —— 列：信源 / 层级 / 首报领先（该源比同故事第二家早多久，中位数）/ 被转述家数 / 立场偏离（5 格微条标出该源落在哪一档 + 数值）。底部结论条（`#FAFAF8`）。
2. **涨落榜** —— velocity 变化排序，正增长 `ink` + 600，负增长 `ink-3` + 500。底部一句结构性观察。

## Interactions & Behavior

- **导航**：故事行 / 必读卡整块可点 → 故事详情页。频道名 → 该频道筛选视图。簇标签 → 簇内故事列表。实体胶囊 → 实体页（下钻层级：全库 → 频道 → 故事页 → 实体页）。
- **引用码**：详情页综述里的 `c1` 可点 → 滚动定位并高亮断言墙对应行（**不要用 `scrollIntoView`**，用容器 `scrollTop` 计算）。
- **hover**：列表行 hover 底色 `#FAFAF8`；胶囊与徽章不做 hover 变化；可点文字 hover 加下划线。
- **图表**：每个图必须提供**表格视图**切换；tooltip 对 hover 与键盘 focus 走**同一路径**。
- **时间窗切换**（24H/72H/7D/30D）与排序切换：客户端重新请求，不做整页刷新。
- **主题切换 `◐`**：浅色 / 深色，写入 localStorage 并在载入时恢复。
- **加载态**：面板骨架用 `#F0EEE9` 块，保持最终布局的行数与高度，避免跳版。
- **错误态**：频道查询返回 422（`BadQuery`，配置错误不是 500）时，在该频道面板内显示查询出错与原因，其他频道照常渲染 —— 沿用后端的失败隔离原则。
- **空态**：结构检测未触发的视图要**显式说明为什么没有**（「这个频道没有链路图，因为 depends 边不足以拓扑排序」），不能只是不渲染 —— 否则用户会以为页面坏了。

## State Management

- `channels`、`activeChannel`、`timeWindow`（24H/72H/7D/30D）、`sortKey`（velocity/breadth/disagreement/updated）

## 深色主题

两套都要经得起看，**深色不是把浅色反过来**。设计稿只给了色板方向（在 Turn 1 各方案底部的深色条里），完整深色稿尚未出：
- 底色降到 `#0E1116`–`#191714` 区间（跟随浅色的暖轴），面板靠**明度分层**抬升一档，而不是靠描边；
- 立场蓝红需**提亮并降饱和**（参考 `#7FA8D4` / `#D96B62`）才能在暗底保持 CVD 分离度；
- 文字三档的对比度下限与浅色一致（≥4.5:1 / ≥3.6:1），不要在深色下偷偷降。

任何配色改动都必须过 dataviz 校验器（CVD 分离度 / 对比度 / 单调性）。
