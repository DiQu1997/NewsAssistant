# 给 Claude Code 的开工包

## 怎么用这个包

1. 把整个 `design_handoff_newsassistant_redesign/` 目录放进仓库根目录（或 `docs/design/` 下），提交。设计稿要进仓库——实现过程中会反复回来量取值。
2. 在仓库根目录起一个 Claude Code 会话，粘贴下面「开工提示词」。
3. **不要让它一次做完八个页面。** 按「分阶段计划」一个阶段一个 PR，每阶段结束用对应截图比对。

打开 `newsassistant-designs.dc.html` 需要同目录的 `support.js`（已附）。在浏览器里直接打开即可，能选中元素、量真实数值。

## 分阶段计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| 0 | Vite 脚手架 + token 层 + 原子组件 + `/dev` 展示页；后端改 serve `web/dist` | 展示页上每个原子件与 README token 表逐项对得上；`▲▼` 全站搜不到彩色 |
| 1 | 路由骨架四层（`/` → `/s/:section` → `/c/:cluster` → `/story/:id`）+ 顶栏 / tab 栏 / 面包屑 + 加载骨架与错误隔离 | 点得通四层，422 时只坏一个面板 |
| 2 | **头版 `5a`** | 与 `screens/5a-front-page.png` 比对；重点检查「为何在头版」说明条与「刚刚更新」流是否真是最新写入序 |
| 3 | **板块页 `5b`**（一个组件跑六个板块）+ 簇折叠展开 | 六个板块只换数据不改代码 |
| 4 | **簇页 `5c`** | 共轴时间带的行标签 / 色块区 / 日期刻度逐像素对齐 |
| 5 | **故事页 `2b`** —— 分歧矩阵是主舞台，占最大面积；引用码可点定位（用容器 `scrollTop` 算，**不要 `scrollIntoView`**） | 矩阵有表格视图切换 |
| 6 | `4a` 市场快照（单轴硬约束）+ `4b` 每日画报 + `4c` 周复盘 | 图例必须写出分档阈值 |
| 7 | 深色主题（明度分层，不是反色；立场蓝红提亮降饱和）+ `localStorage` 持久化 | 深色下文字对比度下限与浅色一致 |

## 需要后端补的东西（阶段 2 之前就要开工，否则首页做不出来）

首页的产品核心是**模型写的综述**和**可解释的排序依据**，现有 API 都没有：

| 需要的字段 | 用在哪 | 说明 |
|---|---|---|
| `section_digest`（每板块一段，每半天重算） | 5a 板块列、5b 板块头 | 不是摘要拼接，是「这个板块这半天发生了什么、共同主题是什么」。今天无新事件时要如实说 |
| `front_page_reason` | 5a 头条的「为何在头版」 | 结构化的筛选依据：改口径的源数、今日新增断言数、分歧结构变化。前端不编 |
| `cluster_digest` + `narrative_drift` | 5c 簇综述、主线漂移 | 漂移要带阈值（聚类中心位移 vs 阈值） |
| `updates` 流（按写入时间倒序，带 delta） | 5a 刚刚更新 | 每条要说「这次更新改变了什么」：`+1 断言`、`分歧 +18` |
| `story.contribution`（簇内占比） | 5c 簇内故事 | |
| 读时 / 关联故事 / `observations` 序列 | 3a / 4a | README 已列 |

## 交给它之后你要盯的三处

1. **首页有没有偷偷变回列表。** 如果板块列里出现第 4、5 条，或者出现「加载更多」，方向就跑偏了。
2. **综述是不是真的模型写的。** 最容易被实现成「取第一条故事的摘要」——那等于没做。
3. **簇页有没有在复述故事。** 簇页上每一块内容都应该是「跨故事才成立」的；如果某块单个故事页也有，它就不该在这。
