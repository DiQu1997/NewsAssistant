# V2 重设计：自底向上的层级化事件体系

2026-08-07 与用户逐层敲定。取代"故事流 + 实体规则频道"的平面结构。

## 原则（先于一切设计决定）

1. **LLM 决断为主，规则只做成本剪枝。** 归属、命名、重要度、层级——一切
   "判断"都由 LLM 做。规则（url_deny 正则、实体倒排召回、IDF 过滤）只允许
   出现在"把 5000 个候选剪到 5 个"这类省钱环节，不允许做最终决策。
   理由（用户原话）：rule base 好用的话这类问题早解决了，轮不到 LLM。
2. **增量 + event-sourcing 保留。** 事件归并依然是序贯裁决而非批量聚类：
   每篇文档为什么归了这个事件，永远有据可查、可回放、可回滚。批量重聚类
   结果漂移且不可审计。同期全局视野由上层的周期归簇补足（见 L4）。
3. **重要度是编辑判断，不是转载计数。** docs/breadth 量的是"被印证程度"，
   天然滞后——大新闻的第一报永远只有一篇。重要度必须在读内容的那一刻由
   LLM 判出来，转载数只做后续修正。

## 分层流水线

```
L0 采集      源 → 条目。url_deny 掐 URL 可识别的品类（成本剪枝）
L1 正文      确定性抽取（trafilatura / feed 摘要即载荷）。零 LLM。
L2 单篇分析  一次 LLM 调用（haiku）：on_topic 门禁 + 结构化产出
L3 事件归并  召回（确定性）+ LLM 裁决 → event（= 现有 stories，不迁移）
L4 层级归簇  周期扫描（8h）：event 归入 arc/saga，自由递归、多父 DAG
L5 域标注    六大域标签在节点命名的同一次调用里顺带产出
L6 UI        头版 = importance×新鲜度混排；下钻 = DAG 逐层展开
```

## L2 单篇分析：字段清单

| 字段 | 用途 |
|---|---|
| on_topic | 主题门禁（政治/地缘/经济/金融/business/科技/重大公卫/重大灾害）|
| claims | 证据原子：宣称墙、综合层引用、分歧检测 |
| entities | 召回索引（确定性倒排的燃料）|
| stance | consensus 标量来源 |
| is_opinion / lang | 评论文降权 / 语言 |
| **summary**（新增）| 1-2 句人话。UI 每篇一行 + 上层归簇的判断材料 |
| **event_signature**（新增）| 一句"谁对谁做了什么"的事件指纹（"美财政部联合日本央行干预日元汇率"）。聚类锚点——标题带媒体角度，不能当锚 |
| **importance_raw**（新增，1-5）| 编辑判断：1=例行公文 2=行业常规 3=行业要闻 4=头版级 5=历史级。第一报即可判，不等印证 |

三个新字段并入现有调用，每篇 +50 输出 tokens，全天 ~$0.5 等价。

## 每层的 token 食谱（第四条原则：逐层递减的视图）

**全文只在 L2 被读一次，且只在输入侧**（haiku 输入便宜，输出是结构化
字段，模型永不复读文章）。L2 之上每一层只拿它做判断所需的最小视图，
层级越高视图越瘦：

| 层 | 输入视图 | 量级 |
|---|---|---|
| L2 | 全文（截断 12K 字符）→ 输出结构化字段 | 读一次，终身复用 |
| L3 | event_signature + summary + 合格实体；候选侧：故事名 + 签名 + 共享实体 | 每篇 ~150-250 tok |
| L4 | 每个 event 一行：签名 + 域 + 活跃度；节点词表：名字 + 一句话入簇标准 | 每 event ~30-50 tok |
| L5 | 零增量（搭 L3/L4 调用的车）| 0 |

L3 现状是宣称 8 条 + 实体 15 个（~500 tok/篇），V2 切到签名 + summary
后预计砍一半以上（cache 写是 assign 成本大头，等比例受益）。**但有一个
诚实的权衡**：裁决 prompt 要求引用决定性判据（日期、数字的吻合），评测
显示分歧集中在需要细节的边界 case（"同为 8 月 5 日标普破 7700"这种）。
所以默认方案保留文档侧宣称 3 条、候选侧砍到 2 条，切换前必须用
eval_assign_model.py 重放对比一致率——瘦身不过评测门不上线。

## L3 事件归并（现 assign，内核不动）

- importance 聚合：`story.importance = max(旗下文档 importance_raw)`，
  在 _update_scalars 里维护。max() 是算术不是判断，不违反原则 1。
- 已知待修：中频行业实体（投行/监管机构）通过 IDF 过滤污染候选列表
  （Angi 财报会召回了 4 个不相关财报会）。修法待评测：IDF 阈值加绝对上限
  或候选加权重下限。动之前用 eval_assign_model.py 重放验证一致率。

## L4 层级归簇（新建）

**结构：自由递归 + 多父 DAG**（用户拍板，2026-08-07）：

- 统一的 node 概念：arc/saga 只是习惯叫法，机制上不区分层级序号，
  node 可以做 node 的父节点，递归深度由 LLM 按需决定。
- 一个 event/node 可以正式属于多个父节点（美日汇率干预 → 同属
  "汇率干预"与"美日关系"）。
- event 层就是现有 stories 表，不迁移不重命名。

**自由度的三条结构性纪律**（防止树长歪，属于契约不是判断规则）：

1. **无单子链**：只有一个子节点的父节点不该存在——没有兄弟就没有
   "归纳"的信息增量，直接用子节点本身。开新父节点须 ≥2 个成员或
   明确的持续性弧（如"俄乌战争"这种确定会持续吸收的）。
2. **无环**：写入 edge 前代码walk祖先链拒环。方向永远从小scope指向大scope。
3. **去重上滚**：任何节点的 docs/breadth 统计 = 后代闭包内 distinct
   文档集（DAG 下同一文档可能经多条路径到达，必须去重）。
   importance 上滚取 max，天然无重复计数问题。

**归簇契约**（继承 topics.py 涌现归簇的全部纪律）：

- 周期扫描，8h 一轮：输入 = 活跃 events（event_signature/summary/实体）
  + 现有节点词表（名字 + 一句话入簇标准，按 last_active 截断）。
- Reuse-first：先复用现有节点，新节点只为新现象开。
- 新节点必须给：命名（≤8 字，中立描述现象本身）+ 一句话入簇标准 + 域标签。
- 不强制归属：真正独立的事件就 standalone，不硬塞。
- 词表持久化（类比 channel_topics），跨轮稳定。

**成本**：活跃 event 每天数百个，8h 一轮 sonnet 批量，与现 topics 阶段同
量级（每天几美元等价以内）。

## L5 域标注

六大域 = 政治 / 地缘政治 / 经济 / 金融 / business / 科技。固定小词表，
在节点命名与 standalone event 裁决的同一次 LLM 调用里顺带标注，不单独花钱。
**channels 彻底废除**（用户拍板）：实体规则频道（any_entities 匹配）是
规则做判断的活标本，职能被域 tab + 层级下钻完全替代。channels.yaml、
频道子主题（topics 阶段）随 P2/P4 退役——topics 的涌现归簇模式升级为
L4 核心机制，不是丢弃是晋升。

## L6 UI（喂给 Claude Design 简报）

- **头版**：importance × 新鲜度混排。高重要度的第一报（单源、低印证）
  直接上头版，带"单源未印证"角标——这是特性不是缺陷，编辑部抢头条
  也是这么干的。热弧（velocity 高的 arc/saga）与突发事件混排。
- **下钻**：saga → arc → event → 文档/宣称墙，逐层展开。多父节点的
  面包屑显示全部归属（"属于：汇率干预 · 美日关系"）。
- **域 tab**：六大域做顶部过滤，不再是平行频道页。

## 不变的部分

论文/博客不是"事件"）、市场/分析师管线、存储分层与归档。
