# 控制台布局原型 + 真实数据页

```
node build.mjs          # 原型页（虚构数据，验证版式与视觉编码）
na snapshot             # Postgres → data/snapshot.json（真实数据导出）
node build-real.mjs     # → real.html（真实数据：总览 + 已合成故事详情，单文件）
```

> 原型页**全部数据均为虚构**，每页均有「示例数据 · 布局原型」标记。
> `real.html`（gitignore，含真实数据、可再生）是阶段 5 真化的第一步：
> 同一套 theme 与编码语法，数据换成真实快照；原型里没有真数据支撑的版块
> （数值源带、断言演变轨道）**直接不出现**，不做假数据混排。
> 综述引用可点开（chip → 原始断言卡片）—— 最高原则 5 的前端面。

## 架构（与 docs/architecture.md、docs/views.md 对应）

**硬编码结构，永不硬编码主题。** 原型按生产架构的形状组织：

| 文件 | 对应生产系统的 | 内容 |
|---|---|---|
| `store.mjs` | 通用存储 | 实体 / 无向共现 / 有向依赖 / 有序状态机 / 数值序列 / 故事 / 断言 / 问题 —— 全部为**通用类型**，条目携带 tags；领域词汇只作为数据里的 label 出现 |
| `channels.mjs` | 保存的查询 | 每个频道只有**过滤器 + 标识色**。没有版面、没有面板、没有领域逻辑 |
| `build.mjs` | 查询执行 + 视图选择 | ① 执行查询 ② **按检测到的数据结构自动选视图**（有向边可拓扑排序→流向图；外生序列可对齐→共轴时间带；共现稠密→网络；有序状态机→阶梯…） ③ 视图注册表：每种结构一个通用渲染器 ④ 布局：默认跨度 + 行填充 |

**新频道 = channels.mjs 加一行。** 演示：`meta-disagreement`（全库分歧）
是一个跨主题的元频道 —— 没有领域过滤器，只按分歧度取断言 —— 零新代码长出来的页面。

跨频道的故事（如出口管制）带多个 tag，会同时出现在多个频道的故事流里，
并标注「也在 X」。

## 编码语法（全局不变量，详见 docs/views.md）

色阶=密度（分位分档，阈值明示）；▲▼=方向（颜色不承载方向）；
蓝↔红+字符=立场；状态色只表示越阈；形状=实体类型（色觉安全）；
绝不双纵轴（归一化基期 100 共轴，终点直标）；tooltip hover 与键盘同路径。
配色改动必须过 dataviz 校验器。

## 已知缺口

- 频道切换标签是惰性的（各页独立静态文件）
- 力导向布局定种子跑固定迭代后静态渲染
- 未接任何真实数据源；"结构检测"检测的是 store 里已典型化的结构，
  生产版本需从抽取产物中识别这些结构（哪些实体间存在稳定有向依赖等）
- 实体页尚未做（下钻层级见 docs/views.md §5）

## 故事详情页

`node build-story.mjs` → `story-export-controls.html`，以跨频道故事
「芯片出口管制调整」为样例。故事页是 L2 层 story 状态（event-sourcing）
的直接可视化：

- **事件时间线**：泳道 = 证据层级（官方与当事方 / 媒体与分析 / 社群），
  阴影区标出传闻→官方文本的时差 —— 这个时差本身就是信息
- **断言演变**：分歧矩阵的时间维展开 —— 谁先说、谁改口（↺）、何时收敛
- **引用 · 独立性**：全部引用带证据层级徽章 + 转述溯源（187 篇 ≠ 187 个信源）
- **故事系谱**：created / absorbed / split / anchor 的事件日志摘录
- **综述**：每句话句末必有引用标记，点击跳转引用条目 ——
  无引用支撑的句子不允许出现
